# wasabi-inventory

TOKYO WASABI わさび食堂の **資材在庫管理アプリ**（フロント側）。

Google Apps Script（GAS）のウェブアプリとして動かしていたものを、
Chrome の Google アカウント切り替えでスタッフが開けなくなる問題を避けるため、
**画面だけを GitHub Pages に移し、GAS は JSON API として裏に回した**ものです。

- スタッフ用: <https://momonewzealand.github.io/wasabi-inventory/>
- 管理用（ももさん専用）: <https://momonewzealand.github.io/wasabi-inventory/admin.html>
  - スタッフ用画面からはリンクしていません。URL を直接知っている人だけが開けます。
  - こちらもホーム画面に追加できます。名前は「在庫管理」、アイコンは
    **濃い緑の地に琥珀色の葉**（スタッフ用は緑の地に白い葉）で見分けられます。

## 使い方（スタッフ）

下のタブで画面を切り替えます。

- **要発注** … 発注が必要なもの／発注済みで入荷待ちのもの。タブの赤い数字は「発注してください」の件数
- **容器 / 食材 / 衛生** … 分類ごとの一覧（スプレッドシートの分類から自動で作られます。
  タブ名も件数も、シートを直せば自動で変わります。アイコンだけは分類名から
  当てているので、新しい分類を作ったときは `common.js` の `lineIcon()` に足してください）
- **棚卸し** … 数量で管理している品目だけを並べる画面。上の **「数える / 移す」** で
  2 つの使い方を切り替えます

### 棚卸しタブの「移す」（拠点をまたぐ移動）

倉庫から食トラに資材を積んだときなど、**場所を移しただけ**のときに使います。
これがないと「倉庫を 25 減らす」「牽引を 25 増やす」と 2 回入力することになります。

1. 「移す」を押す
2. 上の **元 / 先**（倉庫・牽引・自走）を選ぶ。積み込みなら「元 倉庫 / 先 牽引」を一度選ぶだけ
3. 品目ごとに移した数を入れて「移す」を押す

入力欄の下に **「倉庫 175→150　牽引 0→25」** と、押したらどうなるかが出ます。
合計は変わりません（場所が変わるだけなので）。
通知から 15 秒間「元に戻す」で戻せます。

元と先に同じ場所を選ぶと、自動で入れ替わります。

> **注意（実装上のこと）：API に「移動」という命令はありません。**
> 「移動元から引く」「移動先に足す」の **2 通に分けて** `adjustQty` を送っています（`transfer()`）。
> 途中で失敗すると資材が消えたように見えるので、2 通目が失敗したら
> 1 通目を打ち消す 3 通目を送って元に戻します。
> 戻すのも失敗した場合だけは手で直すしかないので、
> 「◯◯の倉庫を 25個 増やして直してください」と、やることを名指しで出します。
> `adjustQty` は送り直すと二重に効くため、自動再送の対象外です。

内訳の「—」は、**その拠点には置いていない**という意味です（倉庫にしかない品目はこうなります）。
入力し忘れではないので、埋める必要はありません。
「—」の拠点で「−1」を押すと、場所の選び間違いを知らせるメッセージが出ます。

画面の上にある **場所（倉庫 / 牽引 / 自走）** が、いま数を増減する対象の拠点です。
「−1」「+1」も、数字を直接入れたときも、ここで選んだ場所の残数が変わります。
カードには 3 拠点の内訳と合計がいつも出ているので、入れる前に確認できます。

- 数量で管理していない品目 … 「なくなった」→「発注した」→「届いた」のボタンだけ
- 数量で管理している品目 … 「−◯」「+◯」と、数字の直接入力

### 「届いた」を押したときの入荷数

数量で管理している品目は、「届いた」を押すとカードの中に
**「いくつ届きましたか？」** の入力欄が開きます。
入れる場所（倉庫 / 牽引 / 自走）と届いた数を入れて「入荷を登録」を押すと、
**残数を増やしてから**「在庫あり」に変わります。

数量を増やさずに「在庫あり」に戻すと、残数が発注点以下のままなので
すぐにまた「要発注」に戻ってきてしまいます。これを防ぐための入力欄です。

- 入力欄の下に「登録すると 計◯◯」と出ます。入荷しても発注点以下のままのときは
  「まだ発注点◯◯以下です」と続けて出るので、追加で頼むかどうかその場で判断できます
  （そのまま登録すれば、正しく「要発注」に戻ります）
- 数がすぐに分からないときは、下の「数がわからない（数量はそのままで「在庫あり」にする）」
  で、これまでどおり状態だけ変えられます
- 登録したあとの通知から「元に戻す」を押すと、**足した数を引いて**「発注済み」に戻します
- 数量で管理していない品目（アルコール消毒液など）は、これまでどおり押すだけで「在庫あり」です

### 増減の刻み

1. **`lot` に値があればその数**。袋やケース単位でしか動かない品目（丼・ふた・カップ・
   割りばし・米など）に入れます。`lot` が 25 なら「−25」「+25」と出ます
2. `lot` が空なら 1 刻み

`lot` はスプレッドシートのロット列で設定します（管理画面からは編集できません）。
**数字だけを入れてください。**「5kg」のように単位まで書くと文字あつかいになり、
読み取れずに 1 刻みに戻ります。0.5 のような小数も入れられます。

以前は「単位が kg・L なら 0.5 刻み」という決めうちも入れていましたが、やめました。
`lot` という決める場所ができたあとでは、こちらが勝手に決めた数が出るだけで、
「5 にしたはずなのに 0.5 になる」という混乱のもとになるためです。

### タブごとに出す情報が違います

縦に長くなりすぎるので、タブによって出すものを変えています（`cardInner(item, mode)`）。

（「移す」モードのカードは別仕立てで、品名・ステータス・元と先の残数・移す数の入力・
プレビュー・「移す」ボタンだけを出します）

| | 要発注 | 分類（容器・食材・衛生） | 棚卸し |
|---|---|---|---|
| 品名・ステータスチップ | ○ | ○ | ○ |
| 合計残数 | ○（「残 0本」） | ○（「計 350個」） | ○ |
| 発注点・発注先 | ○ | − | ○（＋更新日） |
| −1/+1・直接入力 | − | ○ | ○ |
| 3拠点の内訳チップ | − | − | ○ |
| ステータスボタン | ○ | ○（在庫ありの数量管理品を除く） | − |
| 上部の場所セレクタ | 隠す | 出す | 出す |

要発注タブは拠点ごとの操作がないので、場所セレクタごと隠してヘッダーを低くしています。

ボタンを押したあと画面の下に出る通知には、15 秒間だけ **「元に戻す」** が出ます。
押し間違えたらここから戻せます。

### 「在庫あり」ボタン（要発注の品目だけ）

要発注の品目には、主ボタンの横に小さく **「在庫あり」** が出ます。
していない発注を記録せずに、そのまま在庫ありへ戻すためのものです。

ステータスはスプレッドシートに**書き込まれた値**で、発注点と残数から毎回
計算し直しているわけではありません。そのため **発注点を消しても、すでに
「要発注」になっていた品目はそのまま残ります。**
このボタンがないと「発注した」→「届いた」と 2 回押すしかなく、
していない発注を記録することになるため用意しました。

残数が発注点以下のままの品目でこれを押したときは、通知で
「数を入れ直すとまた要発注になります」と断ります。

**発注済みの品目にはこのボタンを出していません。** あちらは「届いた」から
入荷数を入れる流れがあり、そこを飛ばして在庫ありにすると残数が足りないまま
になるためです。数が分からないときは、その流れの中の
「数がわからない（数量はそのままで「在庫あり」にする）」を使ってください。

### ホーム画面に追加する

スマホのブラウザでスタッフ用の URL を開き、
iPhone は「共有」→「ホーム画面に追加」、Android は「メニュー」→「アプリをインストール」。
アプリのように全画面で開けるようになります。

`sw.js` を置いてあるので、圏外でも画面そのものは開きます（在庫の数字は出ません）。
画面のファイルは「まずネットから取りに行き、だめなときだけ手元の控えを使う」ようにしてあるので、
`git push` した新しい版は次に開いたときそのまま反映されます。
どうしても古いままになるときは、`sw.js` の 1 行目あたりの `VERSION` を `v1` → `v2` に上げて push してください。

**在庫データは `sw.js` に一切保存していません。** 古い在庫数が出ると事故になるためです。

### 通信が失敗したとき

GAS は転送のときに、まれに 404 を返すことがあります（GAS 側のくせで、内容が壊れているわけではありません）。
読み込みと、`setQty` / `setStatus` / `updateField` は自動で最大 3 回まで送り直します。

`adjustQty`（−1 / +1）と `addItem`（品目の追加）は**わざと送り直しません**。
送り直すと二重に効いてしまうことがあるためです。失敗したときは画面が元の数字に戻るので、押し直してください。

入荷の登録（「入荷を登録」）だけは `adjustQty` → `setStatus` の **2 通に分けて送ります**。

- 1 通目（数量）で失敗 … 何も変わっていないので、入力した数字を残したまま入力欄が開いたままになります
- 2 通目（状態）で失敗 … 数量はもう入っています。二重に足さないよう画面が覚えていて、
  もう一度「届いた」を押すと**入力欄を出さずに状態だけ**変えます（`receivedSaved`）

## 使い方（管理・ももさん）

`admin.html` を直接開きます。品目ごとに次を編集できます。

発注点 / 単位 / 規格 / 発注先 / 分類

入力欄から離れた時点で自動保存されます。
保存の順番待ちの間は**その欄だけ**が薄い黄色になり、他の欄はそのまま続けて直せます
（GAS の応答に 2 秒ほどかかるため、待たずに次へ進めるようにしてあります）。
保存できると枠が緑になります。

- **発注点に 0 は入れられません。** 0 にすると合計が発注点を下回ることが起きず、
  その品目はいつまでも「要発注」になりません。警告が出て元の値に戻ります。
  発注点を使わない品目は、0 ではなく **空欄** にしてください。
- **削除機能はわざと作っていません。** 誤操作でスプレッドシートから消えると戻せないためです。
  使わなくなった品目は、スプレッドシート側で直接あつかってください。

## API（GAS 側）

エンドポイント（`common.js` の `ENDPOINT`）:

```
https://script.google.com/macros/s/AKfycbwaJlUIpU4orf7L5mrt-AcSE8dL-gfjy8lHs2ZOXh2xUK0dINYv7Lsp5TNe3lZiyV3cFw/exec
```

読み込み: `GET {endpoint}?action=load` → `{ ok:true, items:[...], lines:[...] }`

書き込みはすべて POST。CORS のプリフライトを避けるため
`Content-Type: text/plain;charset=utf-8` にして、本文に JSON の文字列を入れます。

| action | 送るもの | 意味 |
|---|---|---|
| `setQty` | `row, loc, qty` | 残数を直接セット |
| `adjustQty` | `row, loc, delta` | 使用数・入荷数を加減算 |
| `setStatus` | `row, status, isUndo` | ステータス変更 |
| `updateField` | `row, field, value` | `rp` / `unit` / `spec` / `supplier` / `line` |
| `addItem` | `name, line, unit, rp` | 品目の追加 |

`loc` は `soko`（倉庫）/ `ken`（牽引の食トラ）/ `jiso`（自走の食トラ）。
どれも `{ ok:true, items:[...], lines:[...] }` を返します。失敗時は `{ ok:false, error:'...' }`。

> **注意：`items` に入ってくる件数が action によって違います。**
> `updateField` は全件（39件）返しますが、**`adjustQty` と `setQty` は変えた 1 件だけ**を返します。
> そのため画面側では `items` で丸ごと置き換えず、`mergeItems()`（`common.js`）で
> 行番号を突き合わせて上書きしています。丸ごと置き換えると、数量を更新した瞬間に
> その 1 件以外が画面から消えます（実際に一度そうなりました）。
> 全件で置き換えてよいのは `?action=load` の返事だけです。
>
> また、グループのある品目（しょうゆ3サイズなど）は 1 件だけ返ってくると
> 他のサイズに出ている「計」が古いままになるので、書き込みのあとに
> 裏で全件を読み直しています（`refreshGroup()`）。

**GAS の URL を作り直したときは `common.js` の `ENDPOINT` を書き換えてください。**
書き換える場所はここ 1 か所だけです。

### 通信の考え方

起動時に 1 回だけ `action=load` で全件を読み、
そのあとは書き込みの返事に入っている `items` で画面を差分更新します。
全件の読み直しは、右上の更新ボタンを押したときと、
5 分以上ほうっておいた画面に戻ってきたときだけです。

### 起動を速くする工夫

GAS の応答に 1.6〜2 秒かかり、その間まっ白で待たされるのが長く感じられたため、
次の 3 つを入れています。

1. **`common.js` を `<head>` に置く。** 画面を組み立てる `app.js` の解析を待たず、
   読み込まれた時点で `load` を始めます（結果は `bootLoad`）。
2. **`preconnect`。** Google のサーバーへの接続を先に用意しておきます。
   初回の接続作りに 0.8 秒ほどかかっていたのが前倒しされます。
3. **前回の数字を `localStorage` に覚えておく。** 開いた瞬間に前回の数字を出し、
   裏で最新に入れ替えます。開いてから数字が見えるまでが 2 秒 → 0.2 秒ほどになります。

**3 について。** 当初は「端末に何も保存しない」方針でしたが、
起動の待ち時間を減らすため、Momo の判断で入れました。
古い数字を見て発注を判断してしまう事故を防ぐため、次の安全策を付けています。

- 最新に入れ替わるまで、画面上部に
  **「最新の数字を取っています… いま出ているのは 8/13 0:09 時点の数字です」** と出す
- そのあいだ **「−1」「+1」「直接入力」「ステータスのボタン」は押せない**
  （タブの切り替え・場所の切り替え・更新ボタンは使えます）
- 最新が取れなかったときは帯を
  **「最新の数字を取れませんでした」** に変え、**再読み込みボタン**を出す。
  触れない状態は続けたままにする
- 7 日より古い記録は使わない
- 保存しているのは在庫数と品目名だけ。個人情報は含まれません
- 記録は端末の中だけで、外には送りません

キーは `wasabi-inventory:snapshot:v1`（`common.js`）。10KB ほどです。

## セキュリティについて（大事）

このリポジトリは **Public（公開）** です。GitHub Pages を無料で使うための条件です。
そのため、**上の GAS の URL は誰でも見られる状態**になります。
GAS 側は「アクセスできるユーザー: 全員」で公開しているので、
**URL を知った人は在庫データを読み書きできます。**

扱っているのは資材の在庫数だけで、お客様の個人情報や決済情報は入っていません。
とはいえ、気になる場合は次のどれかを検討してください。

1. **リポジトリを Private にして、Cloudflare Pages か Netlify で公開する**
   （どちらも無料。ソースコードは非公開のまま、画面だけを公開できます）
   → いちばん効果があります。GitHub のコード検索で URL を拾われなくなります。
2. **GAS 側で合言葉を確認する**
   すべてのリクエストに決まった文字列を入れて、GAS 側で一致しなければ弾く方法。
   画面のソースを読める人には見えてしまいますが、機械的に URL を拾う相手には効きます。
3. **おかしな書き換えが起きたら、GAS を「新しいデプロイ」で作り直して URL を変える**
   `common.js` の `ENDPOINT` を新しい URL に書き換えれば、古い URL は使えなくなります。

どれも Momo ひとりで判断せず、必要になったら相談してください。

## ローカルで動きを確かめる

`file://` で開くと通信がブロックされます。簡易サーバーを立ててください。

```bash
python -m http.server 8123
```

そのあとブラウザで `http://127.0.0.1:8123/index.html` を開きます。
